## 1. 往復検査の速度と精度(19の敵対的ケース+忠実な40)

敵対的ケースを 9 から 19 に増やした(`testdata/fidelity-adversarial-v1`。仮定の追加と欠落、`>` と `≥`、量化子の順序、別の性質、強い性質(一様連続)、開区間と閉区間、群の仮定の欠落、`sqrt` の定義域など10種)。忠実なものは 19 の忠実な命題に、先に Lean が証明した形式化(21)を足した計 40。各2回(`reasoning` low)。

| 検査 | 偽の承認(悪い命題を通した) | 偽の却下(忠実な命題を落とした) | 遅延 p50 / p90 |
|---|---|---|---|
| 意味審査(1回の呼び出し) | 3/38 | 0/80 | 4.3 / 5.0 秒 |
| 往復・2回(命題だけを見て言い換え、依頼と比較) | **0/38** | 5/80 | 6.0 / 8.2 秒 |
| 往復・1回(言い換えと比較を1つの構造化呼び出しで) | 0/38 | 7/80 | 3.8 / 5.9 秒 |
| 審査 AND 往復・2回 | 0/38 | 5/80 | 並行で p50 6.0 |
| 審査 AND 往復・1回 | 0/38 | 7/80 | 並行で p50 4.3 |
| (`reasoning` を none にすると) 往復・1回 | 0/38 | **30/80** | 2.4 / 3.3 秒 |
| (none) 往復・2回 | 2/38 | 2/80 | 4.6 / 5.4 秒 |

- 1回版は、最初の実行(別の2回)で**斜体に `Field` を2/2通した**(言い換えの段階で依頼が見えるため、依頼に引きずられる)。2回目の実行では通さなかった。**非決定的で、1回版の盲検は弱い。**
- 2回版は `Field` を毎回止めたが、`strict-vs-weak`(`> 0` を `≥ 0` に弱めた命題)を1回目の実行で通した(審査も同様)。1回版と審査はこれを止めた。**検査ごとに見逃しが違うので、全部の AND(本実装)が偽の承認 0 に最も近い。**
- 選択: **既定は 2回版(`roundtrip_mode="two_calls"`)+審査**。偽の却下が少なく、`Field` を安定して止める。`"single"` は設定で選べる(速いが偽の却下が多く、`Field` を通すことがある)。`reasoning: none` は精度が崩れるので使わない。
- 並行化: 2通りの形式化、審査、往復検査、ポートフォリオの証明は、すべて同時に走る。往復検査の2回目(比較)は1回目に依存するため、形式化の後に逐次2回で約 6 秒(p90 8 秒)かかる。**関所のどれかが返らなければ出さない**(`test_every_check_must_have_returned_before_release`)。

## 2. 計算・可否の依頼(形式化が空になった14題)の経路

- 形式化を種類つきにした(`prove`/`decide`/`compute`/`explain`)。**`decide`**: 問われた命題 `P`(否定も答えも書かせない)を形式化し、`P` と `¬P` を同じ関所で試す。**ちょうど一方が証明されたときだけ**答える(両方なら `both_proved` で通常のパイプラインへ。単体テスト済み)。関所は `P`(モデルが書いた部分)に対して行い、はい/いいえは Lean が決める。**`compute`**: 式だけを形式化(許可リスト文法)し、`∃ v : T, 式 = v := ⟨_, by norm_num <;> rfl⟩` で Lean に値を作らせ(`#eval` も `native_decide` も使わない)、証明項の証人から値を読み、閉じた命題 `式 = 値` を**ふつうのポートフォリオで再証明**する(値は数値か分数だけ受け入れ、式そのものが返ったら却下)。2通りの形式化の式の値が Lean 上で一致することを一致検査とする。
- 実 Lean で値を導出できた式(統合テスト、`tests/integration/test_automation_portfolio_real.py`): `2^10+3 = 1027`、`1/2+1/3 = 5/6`、`∑_{k<11} k = 55`、`∫_0^1 x^2 = 1/3`、`det !![1,2;3,5] = -1`、`C(5,2) = 10`、`√16 = 4`、`5! = 120`。誤った値(7)は再証明で必ず落ちる。`deriv (fun x => x^3 - 3x) 2` のように Lean が簡約できない式は値を作らない(捏造しない)。
- **100題での回収は 0 題**(答えた題として): 14題の内訳は、`explain` と分類されて通常のパイプラインへ 5(正しい扱い)、`decide` と分類 5(答えた 0。1題は Lean が「いいえ」を証明したが、閉じた手に誠実なひな形がなく説明にモデルが要る `seed-linear_system_inconsistent`、1題は関所で不合格、3題は自動化で `P` も `¬P` も証明できず)、残り4題は `prove` と分類され証明できず。**`compute` と分類された依頼は 0 件**(モデルが「導関数を求めよ」を `prove` と分類した)。誤答 0。
- 残る課題: 分類の精度(`compute` への振り分け)、`decide` の `¬P` を閉じる自動化の不足(単射でない、有理数でない、など)。

## 4. 許可リストと `autoImplicit` で失った題の回収

文法は緩めていない。安全な正規化だけ。
- **`let`(与えられた命題のカード、`la_v6_nonzero_maps_zero_composite`)**: `let p := E; …` を Python の代入で巻き上げ(`p.comp q` のような項への射影も)、巻き上げた命題を通常の文法に通す。**カードの命題だけ**、元の `let` の形と巻き上げた形が同じ `Prop` であることを、サンドボックス内で `Iff.rfl` で Lean に確認させる。意味を変える巻き上げ(`≠` を `=` に書き換えた形)は Lean が拒否する(統合テスト)。100題の通しで `let_hoisted` が適用され、証明の段階へ進んだ(証明は予算内に終わらず、答えには至らなかった)。
- **変数名 `λ`**: `λ` が束縛変数として使われ、ラムダとしては使われていないときだけ `lam` に改名(`=>`・`↦` が後に続く `λ`、新しい名前が既に使われている場合は改名しない)。`pq-distinct-eigenvalues-linear-independence` は改名後に Lean が elaborate し、証明の段階に進んだが、閉じなかった。
- **`autoImplicit` を切って elaborate できなくなった題**: 変えていない(命題が自由変数を含むものを `∀` に勝手に束縛すると意味が変わるため)。通しでは `seed-rank_nullity` の `Field` 版が1題、`statement_not_elaborated` になった。
